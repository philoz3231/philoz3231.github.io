GitHub Pages 블로그를 운영하다 보면 이런 상황을 자주 마주친다. 쓸 내용은 있다.
그런데 막상 앉아서 마크다운 파일을 열고, 구조를 잡고, 배포까지 하려면 생각보다
에너지가 많이 든다. 결국 글감은 메모앱 어딘가에 잠들어 버린다.

이 문제를 Claude Code의 원격 세션 기능으로 해결해봤다.

## 문제: 초안까지의 거리가 너무 멀다

GitHub Pages 기반 블로그는 구조가 명확한 대신 글 하나를 올리는 데 단계가 많다.

1. 로컬에서 `_posts/YYYY-MM-DD-title.md` 파일 생성
2. front matter 작성
3. 본문 마크다운 작성
4. 빌드 확인
5. 커밋 & 푸시

짧은 글감 하나를 공개 가능한 수준으로 다듬는 데 드는 노력이 적지 않다.
특히 이동 중이거나 모바일 환경이라면 더욱 그렇다.

## 해결: 모바일에서 대화로 초안 작성

Claude Code는 웹 브라우저에서 세션을 유지할 수 있다. PC 없이 스마트폰 브라우저만으로
리포지토리에 연결된 Claude와 대화할 수 있다는 뜻이다.

활용 방법은 단순하다.

1. 모바일 브라우저에서 Claude Code 원격 세션 접속
2. 짧은 글감(메모, 키워드, 경험 요약)을 대화로 전달
3. 인터뷰 형식으로 살을 붙여 초안 완성
4. `_posts`에 바로 저장 및 커밋

<img src="/assets/img/mobile-claude-code-blog.png" alt="모바일에서 Claude Code로 블로그 초안을 작성하는 화면" width="320" />

PC를 열지 않아도 이동 중에 대화하듯 초안을 완성할 수 있다.
마크다운 문법이나 파일 구조를 직접 다룰 필요가 없다.

## 실제로 써보니

가장 큰 변화는 **글감이 쌓이지 않는다**는 점이다. 짧은 메모 수준의 내용도
대화를 통해 빠르게 공개 가능한 글로 전환된다. GitHub Pages처럼 배포 과정이
있는 블로그에서도 모바일 작성 → 저장 → 푸시까지 한 흐름으로 이어진다.

Velog 사용자라면 완성된 초안을 복사해서 올리는 방식으로 동일하게 활용할 수 있다.

글을 쓰는 데 드는 마찰을 줄이고 싶다면, 에디터보다 대화창이 더 가까울 수 있다.

---

## 부록: 이 포스트를 작성한 스킬 코드

이 글은 `.claude/commands/mobile-blog-writer.md` 스킬을 사용해 모바일에서 작성됐다.
같은 환경을 구성하려면 아래 파일을 리포지토리에 추가하면 된다.

스킬은 인터뷰 → 초안 → 저장 → 커밋 → PR 생성까지 한 흐름으로 처리한다.
이미지는 GitHub 이슈 댓글창에 붙여넣기하면 생성되는 CDN URL을 전달하면 자동으로 받아서 저장한다.

```md
<!-- .claude/commands/mobile-blog-writer.md -->
모바일 메모나 짧은 글감을 인터뷰식으로 받아 외부 공개 가능한 Jekyll 블로그 포스트로 작성한다.
작성 완료 후 파일 저장, 커밋, PR 생성까지 한 흐름으로 처리한다.

사용자 요청:

$ARGUMENTS

기본 원칙:

- 항상 한국어로 대화한다.
- 사용자가 구조화된 입력을 주지 않았다면 대화형 인터뷰 모드로 시작한다.
- 인터뷰 모드에서는 한 번에 질문 하나만 한다.
- 질문은 짧고 답하기 쉽게 만든다.
- 이미 답한 내용은 다시 묻지 않는다.
- 4~6문답 안에 초안 작성을 시작한다.
- 사실처럼 보이는 허구를 추가하지 않는다.
- 공개용 글이므로 과장, 광고성 표현, 민감 정보 노출을 피한다.

입력 모드:

1. 즉시 작성 모드
- 사용자가 주제, 독자, 톤, 핵심 메모, 이미지 역할 등을 충분히 줬다면 바로 초안을 작성한다.

모바일 구조화 입력 예시:

주제:
독자:
톤:
길이:

핵심 메모:
-
-
-

반드시 넣을 내용:
-

빼고 싶은 내용:
-

이미지:
1. URL 또는 설명 - 이 이미지가 전달해야 할 의미
2. URL 또는 설명 - 이 이미지가 전달해야 할 의미

2. 대화형 인터뷰 모드
- 사용자가 글감만 짧게 주면 필요한 정보만 순서대로 묻는다.
- 질문 우선순서:
  1. 이 글을 누가 읽는지
  2. 가장 강조할 장면 또는 포인트 2~3개
  3. 이미지 유무와 각 이미지의 역할
  4. 원하는 톤
  5. 반드시 넣을 내용 또는 빼야 할 내용
- 길이는 사용자가 말하지 않으면 1200~1800자 정도로 추정한다.
- 아래 조건 중 3개 이상 충족 시 추가 질문을 멈추고 초안을 작성한다.
  - 독자가 정해짐
  - 핵심 장면 또는 핵심 메시지 2개 이상 확보
  - 이미지 1장 이상 또는 이미지 없음 확인
  - 톤 정해짐
  - 반드시 넣을 내용 확인

질문 예시:

- "이 글은 누가 읽는 걸 상정하면 될까?"
- "가장 기억에 남는 장면 2~3개만 적어줘."
- "이미지 있어? 있으면 GitHub 이슈에 붙여넣기 하면 URL 생기는데 그거 주면 돼. (이슈 저장 안 해도 됨)"
- "톤은 담백한 후기, 정보성 후기, 감성 기록 중 어느 쪽에 가깝게 쓸까?"

이미지 처리 규칙:

- 사용자가 이미지 URL을 주면 curl -L -o assets/img/<slug>-<n>.png "<URL>" 로 다운로드해서 저장한다.
- 아이폰에서 이미지를 공유하는 가장 쉬운 방법:
  GitHub 앱이나 브라우저에서 아무 이슈나 열고 댓글창에 이미지를 붙여넣으면
  이슈를 저장하지 않아도 https://github.com/user-attachments/... URL이 바로 생긴다.
  그 URL을 전달하면 자동으로 받아서 저장한다.
- 이미지 URL이 없으면 자리표시자 경로를 본문에 남기고 어느 문단 뒤에 들어갈지 주석으로 표시한다.
- 저장된 이미지 경로는 /assets/img/<파일명> 형식으로 포스트 본문에 반영한다.

글 구조 선택:

- 경험/후기: 도입 -> 상황 설명 -> 핵심 경험 2~4개 -> 정리
- 개발 기록: 문제 -> 시도 -> 해결 -> 배운 점
- 비교 글: 비교 기준 제시 -> 항목별 비교 -> 결론
- 튜토리얼: 배경 -> 준비물 -> 단계별 설명 -> 주의점
- 회고: 목표/맥락 -> 잘한 점 -> 아쉬운 점 -> 다음 액션

구조가 애매하면 경험/후기 형식을 기본값으로 사용한다.

출력 형식:

- 기본 출력은 게시 가능한 Jekyll 마크다운 포스트다.
- 아래 front matter를 기본값으로 사용한다.

---
layout: post
title: 제목
description:
tags: [tag1, tag2]
categories: [blog]
---

- 첫 문단에서 글의 맥락을 분명히 제시한다.
- 소제목은 스크롤 중에도 의미가 보이게 작성한다.
- 이미지가 있으면 관련 문단 바로 뒤에 배치한다.
- 이미지 경로가 없으면 자리표시자 경로를 남기고 어떤 이미지가 어느 문단 뒤에 들어갈지 적는다.

품질 점검:

- 첫 3문장에서 주제와 상황이 드러나는가
- 메모를 늘여 쓴 듯한 반복이 없는가
- 소제목만 읽어도 흐름이 보이는가
- 사용자가 제공하지 않은 구체적 사실을 꾸며 넣지 않았는가
- 이미지가 본문과 자연스럽게 연결되는가
- front matter 포함 여부를 확인했는가

파일 저장 및 PR 생성 규칙:

- 사용자가 초안만 원하면 채팅으로만 보여준다.
- 사용자가 저장 또는 포스팅을 원하면 아래 순서를 자동으로 실행한다:

  1. 파일 저장
     - _posts/YYYY-MM-DD-slug.md 형식으로 파일을 만든다.
     - slug는 제목을 기반으로 ASCII 하이픈 케이스로 정리한다.
     - 이미 같은 날짜와 유사 제목 파일이 있으면 덮어쓰지 말고 사용자에게 알린다.
     - 이미지가 있으면 assets/img/ 에도 저장한다.

  2. 브랜치 생성 및 커밋
     - 브랜치명: post/<slug>
     - 포스트 파일과 이미지를 함께 커밋한다.
     - 커밋 메시지: "Add post: <제목>"

  3. 푸시
     - git push -u origin post/<slug>

  4. PR 생성
     - gh pr create 로 PR을 만든다.
     - PR 제목: 포스트 제목과 동일하게
     - PR 본문에는 포스트 description과 주요 변경 파일 목록을 포함한다.
     - PR URL을 사용자에게 보여준다.

후속 옵션:

- 바로 발행용으로 다듬기
- 조금 더 짧게 줄이기
- 제목 후보 3개 더 보기
- _posts에 저장하고 PR 만들기

사용자 요청이 비어 있으면 먼저 주제나 글감을 한 줄로 물어본다.
```
