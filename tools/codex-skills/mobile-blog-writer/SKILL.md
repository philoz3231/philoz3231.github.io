# 모바일 블로그 작성기

## 개요

사용자 입력이 짧고 거칠다는 전제를 유지하라. 메모를 그대로 늘리지 말고, 맥락을 보강해 읽히는 글로 재구성하라.

이 저장소는 Jekyll 블로그이므로 최종 결과는 게시 가능한 마크다운 포스트를 기본 출력으로 삼아라. 사용자가 원하면 발행 전 초안, 제목 후보, 요약문, 태그 후보를 함께 제공하라.

입력 방식은 두 가지를 지원하라.

- 즉시 작성 모드: 사용자가 구조화된 입력을 한 번에 주면 바로 초안을 작성한다.
- 대화형 인터뷰 모드: 사용자가 글감만 던지면 필요한 정보만 짧게 하나씩 물어본 뒤 초안을 작성한다.

## 기본 절차

1. 입력을 정리하라.
2. 글의 목적과 독자를 추정하라.
3. 부족한 맥락을 최소한으로 보완하라.
4. 공개 가능한 문장으로 다시 작성하라.
5. Jekyll 포맷으로 정리하라.
6. 최종 검수를 수행하라.

## 모드 선택

입력이 이미 충분히 구조화되어 있으면 즉시 작성 모드로 진행하라.

사용자가 아래처럼 말하면 대화형 인터뷰 모드로 전환하라.

- "이걸 글로 써줘"
- "글감만 줄게, 필요한 건 물어봐"
- "하나씩 질문해줘"
- "모바일에서 쓰기 쉽게 진행해줘"

입력이 아주 짧고 아래 항목이 3개 이상 비어 있으면 인터뷰 모드를 기본값으로 사용하라.

- 독자
- 톤
- 핵심 메모
- 이미지 역할
- 반드시 넣을 내용

사용자가 "그냥 알아서 써줘"라고 하면 질문 수를 최소화하고 기본값으로 진행하라.

## 대화형 인터뷰 모드

모바일에서는 긴 템플릿 입력보다 짧은 문답이 더 안정적이다. 인터뷰 모드에서는 한 번에 하나의 질문만 하라.

질문 우선순서는 아래 순서를 기본값으로 삼되, 이미 확보한 정보는 건너뛰어라.

1. 이 글을 누가 읽는지
2. 가장 강조할 장면이나 포인트 2~3개
3. 이미지 유무와 각 이미지의 역할
4. 원하는 톤
5. 꼭 넣어야 할 내용 또는 빼야 할 내용

질문 수는 가능한 4~6회 이내로 제한하라. 정보가 충분해지면 추가 질문을 멈추고 초안 작성을 시작하라.

질문은 짧고 답하기 쉽게 작성하라.

- 좋은 예: "이 글은 누가 읽는 걸 상정하면 될까?"
- 좋은 예: "가장 기억에 남는 장면 2~3개만 적어줘"
- 좋은 예: "사진 넣을 게 있으면 장면만 적어줘. 파일명 없어도 돼"
- 나쁜 예: "독자, 톤, 분량, 이미지 전략, 강조 포인트를 한 번에 정리해줘"

질문이 끝나면 내부적으로 입력을 아래 형식으로 정리한 뒤 글을 작성하라.

- 주제
- 독자
- 톤
- 길이
- 핵심 메모
- 이미지와 역할
- 반드시 넣을 내용
- 제외할 내용

대화형 질문 예시는 [references/interview-mode.md](./references/interview-mode.md)를 따른다.

## 입력 정리

사용자가 길게 설명하지 않아도 아래 항목으로 재정리하라.

- 주제
- 핵심 메모
- 독자
- 원하는 톤
- 원하는 길이
- 포함할 이미지와 각 이미지의 역할
- 반드시 넣을 내용
- 빼야 할 내용

입력이 부족하면 합리적으로 추정하되, 추정한 항목은 결과에 반영하기 전에 짧게 명시하라.

모바일 입력은 종종 문장보다 파편 메모에 가깝다. 메모를 시간 순서, 중요도 순서, 문제-해결 순서 중 하나로 재배열하라.

모바일 입력 형식 예시는 [references/mobile-input-format.md](./references/mobile-input-format.md)를 따른다.

인터뷰 모드에서는 사용자 답변을 매 턴마다 누적 정리하되, 이미 답한 내용을 반복해서 다시 묻지 말라.

## 글 구조 선택

아래 중 가장 자연스러운 구조를 고르라.

- 경험/후기: 도입 -> 상황 설명 -> 핵심 경험 2~4개 -> 정리
- 개발 기록: 문제 -> 시도 -> 해결 -> 배운 점
- 비교 글: 비교 기준 제시 -> 항목별 비교 -> 결론
- 튜토리얼: 배경 -> 준비물 -> 단계별 설명 -> 주의점
- 회고: 목표/맥락 -> 잘한 점 -> 아쉬운 점 -> 다음 액션

구조가 애매하면 경험/후기 형식을 기본값으로 사용하라.

## 작성 규칙

- 첫 문단에서 글의 맥락을 분명히 제시하라.
- 소제목은 스크롤 중에도 의미가 보이게 작성하라.
- 한 문단에는 하나의 중심 메시지만 두어라.
- 과장, 허세, 근거 없는 단정은 제거하라.
- 모바일 메모 특유의 중복 표현과 생략된 주어를 보정하라.
- 사용자가 제공하지 않은 사실은 꾸며내지 말고, 필요한 경우 일반적 수준의 연결 문장만 보완하라.
- 설명이 필요한 이미지에는 본문과 연결되는 문장을 먼저 쓰고 이미지를 배치하라.
- 이미지가 여러 장이면 각각의 역할이 겹치지 않게 하라.
- 공개용 글이라면 사적인 내부 정보, 식별 가능한 개인정보, 확인되지 않은 타인 평가를 노출하지 말라.

## Jekyll 포스트 출력

기본 출력은 아래 순서를 유지하라.

1. front matter
2. 제목
3. 도입부
4. 본문
5. 이미지 블록
6. 마무리

이 블로그의 포스트 형식은 [references/jekyll-post-template.md](./references/jekyll-post-template.md)를 따른다.

이미지 경로를 사용자가 주지 않았다면 자리표시자 형식으로 남겨도 된다. 이 경우 어떤 이미지가 어느 문단 뒤에 들어가야 하는지 함께 적어라.

## 품질 점검

결과를 내기 전에 아래를 스스로 확인하라.

- 초안 메모를 그대로 나열한 흔적이 남아 있지 않은가
- 글 첫머리만 읽어도 주제와 맥락이 보이는가
- 각 소제목이 실제 내용을 대표하는가
- 이미지가 본문 흐름을 끊지 않는가
- 불필요한 미사여구가 과하지 않은가
- 외부 공개 시 민감할 내용이 남아 있지 않은가

세부 점검 항목은 [references/publication-checklist.md](./references/publication-checklist.md)를 따른다.

## 출력 옵션

사용자가 요청하면 아래를 추가하라.

- 제목 후보 3개
- 짧은 요약문
- 태그 후보
- slug 후보
- SNS 공유용 짧은 소개문

## 금지 사항

- 사실처럼 보이는 허구를 추가하지 말라.
- 사용자 메모의 순서를 그대로 유지해야 한다고 가정하지 말라.
- 이미지 설명 없이 이미지만 나열하지 말라.
- 공개용 글인데 내부 메모체를 남기지 말라.
- 지나치게 광고성인 어조를 기본값으로 사용하지 말라.
- 모바일 인터뷰 중 한 번에 여러 질문을 쏟아내지 말라.
